- Gestor: **pnpm**; dependencias **exactas** (sin caret `^`).

- Prohibido `export default`, salvo API routes y `.astro` (usar `export const`).
- Sin comentarios en el código.
- Tailwind v4: prohibido el valor arbitrario cuando existe clase canónica (`aspect-[9/16]` → `aspect-9/16`, `w-[640px]` → `w-160`, escala spacing ×4px).
- Al probar (`astro dev`, Playwright, `wrangler dev`), cerrar siempre el servidor y liberar el puerto 4321 (`taskkill` del PID LISTENING) antes de terminar.
- Sin `hreflang`/SEO inconsistente: cada página actualiza canonical + hreflang de su locale.

## Riesgos y notas

1. **Premium**: el pago real de gift cards (Wix Payments) y cualquier cobro por adelantado requieren sitio Wix premium; se parketan hasta que el owner pague. Las reservas online **ya funcionan** (create responde `RESERVED` en trial); las fases 0/1/3/4 no dependen del premium.
2. **Scopes de API key**: la API key debe tener permisos "Manage restaurant reservations" (+ lectura de menús); si algún endpoint rechaza API key → usar OAuth client_credentials como fallback backend.
3. **Fragment en social login**: Google/Facebook devuelven `code`/`state` en el fragment (`#...`), invisible para el servidor → el callback es página client-side + `POST` a `/api/auth/session` para cookies HttpOnly. Allow-list de redirect URIs del OAuth app registrada en step-12 (`/api/auth/callback` y `/auth/callback`, localhost + dominio), vía `PATCH oauth-app/v1` con `mask.paths`. Hoy incluye también `nami-sushi.nami-sushi.workers.dev` y los logins localizados.
4. **Traducciones → deploy**: resuelto en step-22 con runtime translations (API Wix + KV, cambios del dashboard visibles en ~5 min, purga por `cache-tag`). El fallback es el JSON del build; el push/pull del CLI sigue vivo para seed/roundtrip.
5. **`@wix/sdk` y Workers**: fetch estándar, compatible con Workers (verificado en step-02); `prerenderEnvironment: 'workerd'` es obligatorio en el adapter para que el prerender resuelva `cloudflare:workers`.
